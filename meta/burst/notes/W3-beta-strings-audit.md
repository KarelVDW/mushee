# W3 — beta-wording launch audit (2026-09-05)

Scope: `apps/web/src` and `apps/api/src`, case-insensitive grep for `beta`,
`waitlist`, `early access`, `invite`. Tests, e2e, migrations and `pitch-scan.ts`
(the `beta` there is a parabolic-interpolation variable) are excluded. Pure
identifiers (`betaStatus`, `BetaService`, `BETA_PLAN`, query keys, DTO filter
names, code comments) are summarised per file rather than listed line by line —
none of them is user-facing.

Gating column: **build** = `NEXT_PUBLIC_BETA_MODE` (web, baked at build);
**runtime** = `BETA_MODE` / `isBetaMode()` (API) or the server's `betaMode`
field mirrored to the client; **tier** = keyed on the user's `tierId === 'beta'`
(NOT on the flag — survives the flip for grandfathered accounts); **no** =
unconditional.

## Cross-check with `deploy/runbooks/end-of-beta-launch.md`

- §4.1 (`BETA_MODE: 'false'` in the production overlay) covers every **runtime** row above.
- §4.2 (`NEXT_PUBLIC_BETA_MODE=false` + Vercel redeploy) covers every **build** row; the runbook's list "landing CTA, pricing buttons, the /pricing tier ladder, signup messaging" is complete except it does not name the **onboarding step 7** (`BetaPlanStep`), the **minute-pack upsell in `RecordingDialogs`**, and the two **JSON-LD `'Solkey Beta'` offers** — all flip with the same env var, so no extra action, but worth adding to the smoke list (§4.3: check onboarding shows the plan picker and `view-source` of `/` has the paid offers).
- §4.3 smoke expects `/beta` to show "you're in" for an approved user — confirmed, `beta/page.tsx:45` renders it whenever `status !== 'pending' || !betaMode`.
- §1 lawyer review of `/terms` + `/privacy` is the only place the runbook touches copy that is **not** behind a flag. The runbook does not spell out that `terms/page.tsx` §3 and `privacy/page.tsx:160` contain hard-coded beta sentences — add those two edits (and the `LAST_UPDATED` bump) as explicit checklist lines.
- §3 "Grandfather them … can upgrade any time" is **contradicted by the settings page**: `settings/page.tsx` keys on `tierId === 'beta'`, so grandfathered users keep seeing "Solkey is in closed beta — … Paid plans arrive at launch" and get **no upgrade / manage / pack button** (`:270,281,300`). If option 1 is chosen, that copy and gating must change before the flip; if option 2 (`UPDATE … SET "tierId"='free'`) is chosen, nothing is needed. The runbook should state this dependency.
- Nothing in the runbook is missed by the code side: no `invite`/`early access` gating exists anywhere (the only `early access` hit is a Studio marketing bullet; the only `invite` hit is a code comment in `onboarding/page.tsx:136`).
